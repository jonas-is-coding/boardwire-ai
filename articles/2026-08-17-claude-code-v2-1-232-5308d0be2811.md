# Claude Code v2.1.232

<h2>What's changed</h2>
<ul>
<li>Subagent forking is now on by default: a <code>subagent_type: "fork"</code> subagent inherits the full conversation and prompt cache, and non-teammate agent spawns in interactive sessions now run in the background by default</li>
<li>Type <code>@</code> in the prompt to mention another Claude session by name; Claude then uses <code>SendMessage</code> to reach that session directly</li>
<li><code>SendMessage</code> now delivers to a bare name that exactly matches one live session, instead of asking to confirm with a ref first</li>
<li>Interactive sessions on one machine now keep unique names: starting or renaming a session to a name another live session already uses gives it a <code>name-word-word</code> variant and tells you</li>
<li>Added <code>/config</code> rows for "Dialog expiry" and "Messages from your other sessions" (cross-session inbound accept/hold/refuse)</li>
<li>Added secret redaction for GitLab token families (<code>glrt-</code>, <code>gloas-</code>, <code>glptt-</code>, <code>glagent-</code>, <code>glimt-</code>, <code>glsoat-</code>, <code>glcbt-</code>, <code>glft-</code>, <code>glffct-</code>) and full redaction of routable <code>glpat-</code>/<code>gldt-</code> tokens; the <code>glab</code> CLI config store gets the same sandbox and credential-path protection as <code>gh</code></li>
<li>Added GitLab support to plugin marketplaces: bare <code>gitlab.com</code> repo URLs (including nested subgroups) now clone like <code>github.com</code> URLs, and clone auth-failure hints name your actual git host</li>
<li>Settings: <code>additionalMarketplaces</code> and <code>allowedMarketplaces</code> are now accepted as friendlier aliases for <code>extraKnownMarketplaces</code> and <code>strictKnownMarketplaces</code></li>
<li>Enterprise policy: a url-typed <code>blockedMarketplaces</code> entry for a bare repo URL keeps blocking that URL when the CLI classifies it as a git clone</li>
<li>Gateway: the <code>desktop:</code> overlay now accepts every released Desktop setting (was 11 hand-listed keys), validated at boot against Desktop's own schema; unknown or invalid keys fail boot</li>
<li>Gateway: empty <code>managed.policies[].match.groups</code>/<code>admin.admin_groups</code> entries and malformed <code>email_domain</code> values (empty, or containing <code>@</code>, whitespace, or commas) now fail at boot instead of silently matching no one or granting admin access</li>
<li>Fable 5 is offered as an advisor in <code>/advisor</code> again for organizations with Fable access, with usage-credits consent set up through <code>/model fable</code></li>
<li>Fixed a PowerShell permission bypass where variable-writing parameters could silently overwrite <code>$PSDefaultParameterValues</code> and redirect later commands' file access</li>
<li>Fixed a Windows permission bypass where Git Bash followed Cygwin-style symlinks that path validation saw as regular files; writes through them now require permission approval</li>
<li>Fixed nested git repositories inheriting trust from a parent directory; each repository now requires its own trust confirmation</li>
<li>Fixed MCP connections hanging for the full 30-second connect timeout when a server fails to answer or sends a malformed reply to the protocol-version probe</li>
<li>Fixed Remote Control sessions hosted by a bridge inside a cloud session inheriting that session's transcript or credentials</li>
<li>Fixed Remote Control sessions started from Claude Desktop or an IDE appearing as a new claude.ai session each time the local session was resumed; they now reattach to the existing one</li>
<li>Fixed Remote Control sessions appearing unreachable to newly attached clients while idle</li>
<li>Fixed Remote Control bridge sessions not restoring conversation history when the session worker restarts</li>
<li>Remote Control: resuming a conversation whose session was deleted from claude.ai or the app now starts a replacement instead of failing with a message about your login (regressed in v2.1.227)</li>
<li>Fixed Cloud gateway <code>/login</code> exiting silently or leaving an unresponsive terminal after "Press Enter to continue" when managed settings failed to load; the reason is now shown</li>
<li>Fixed voice mode on native builds getting stuck on "listening…" when the voice service rejected the connection; the rejection is now shown immediately</li>
<li>Fixed mTLS client certificate rotation requiring a restart; Claude Code now reloads the rotated cert and key automatically on connection errors</li>
<li>Fixed malformed AWS or Vertex region values being used to build request URLs; they now fall back to the default region</li>
<li>Fixed stream idle timeout errors failing the request instead of recovering on Bedrock, Vertex, and gateway deployments</li>
<li>Fixed content-sized overlays containing truncated text rendering one column too wide, and start-truncated text collapsing to an ellipsis</li>
<li>Fixed a stray garbled character where a long shell-command or agent-description preview was cut off mid-emoji</li>
<li>Fixed a startup race that could silently unregister a plugin marketplace due to concurrent writes to <code>known_marketplaces.json</code></li>
<li>Fixed <code>/update</code> and <code>/tui</code> refusing to restart while work that survives the relaunch was running</li>
<li>Fixed usage-limit guidance suggesting unavailable slash commands in SDK and remote sessions</li>
<li>Fixed the consent message for interactive <code>--advisor fable</code> launches, which told you to run <code>/model fable</code> in an interactive session that had just exited</li>
<li>Improved fullscreen streaming: long sessions stay responsive because the whole conversation is no longer re-normalized on every update</li>
<li>Improved the managed settings approval dialog: shows endpoint URLs, uses clearer wording for telemetry-only changes, skips routine OpenTelemetry options, and requires approval for server-managed sandbox binary overrides (<code>sandbox.bwrapPath</code>, <code>sandbox.socatPath</code>, <code>sandbox.ripgrep</code>)</li>
<li><code>/feedback</code> and <code>/bug</code> now open immediately when invoked while Claude is responding, instead of waiting for the turn to finish</li>
<li><code>/plugin install plugin@marketplace</code> now refreshes the marketplace first, so newly published plugins install without a manual marketplace update</li>
<li><code>/code-review</code> at high, xhigh, and max effort now runs in a background agent like the other levels</li>
<li>Pasted and clipboard images are read without blocking the event loop</li>
<li>Remote Control now keeps reconnecting for about 30 minutes after a network blip and no longer drops after a few blips spread across an hour</li>
<li>Remote Control: resuming a conversation no longer silently takes Remote Control away from another Claude Code on the same machine that still has it; run <code>/remote-control</code> there to move it</li>
<li>Updated agent panel: completed subagents hide immediately with a <code>/tasks</code> footer hint, and the "↓ N more" overflow indicator moved left for visibility</li>
<li>Remote Control: the terminal now says whether a session was taken over by another device, ended from another app, or deleted, and stops suggesting a reconnect that would undo it</li>
<li>Bash input redirections (<code>&lt; file</code>) are now permission-checked like their argument spellings on all platforms</li>
<li>Shortened the message shown when resuming a completed background agent</li>
<li>Cowork sessions no longer inline external @-imports from user-scope memory files</li>
<li>Hardened the auto-generated cross-session messaging socket directory on shared <code>/tmp</code>: a pre-planted symlink or another user's directory is now refused instead of used</li>
<li>Hardened the Linux filesystem sandbox against a protected-path bypass</li>
<li>Changed <code>sandbox.ripgrep</code> to be honored only from user, managed, and <code>--settings</code> settings; project settings can no longer override the sandbox's ripgrep binary</li>
<li>Removed the startup tip suggesting you create custom subagents, and the matching nudge in the <code>/powerup</code> tour</li>
</ul>

This story surfaced via Claude Code Releases. For the original details and any numbers we have not confirmed here, follow the source below.
