# langchain==1.4.0a2

<p>Alpha preview of <code>langchain.mcp</code> — a first-party adapter that turns any MCP server into LangChain tools you can hand straight to <code>create_agent</code>.</p>
<p>Connection handling is <a href="https://gofastmcp.com/clients/client" rel="nofollow">FastMCP</a>'s, so its client features are available as-is rather than re-implemented behind a narrower interface.</p>
<div class="highlight highlight-source-shell notranslate position-relative overflow-auto"><pre>pip install <span class="pl-s"><span class="pl-pds">"</span>langchain[mcp]==1.4.0a2<span class="pl-pds">"</span></span></pre></div>
<h2>Connect</h2>
<p><code>MCPAdapter</code> takes any target <code>fastmcp.Client</code> accepts — transport is inferred, so there is one entry point rather than one per protocol.</p>
<div class="highlight highlight-source-python notranslate position-relative overflow-auto"><pre><span class="pl-k">from</span> <span class="pl-s1">langchain</span>.<span class="pl-s1">agents</span> <span class="pl-k">import</span> <span class="pl-s1">create_agent</span>
<span class="pl-k">from</span> <span class="pl-s1">langchain</span>.<span class="pl-s1">mcp</span> <span class="pl-k">import</span> <span class="pl-v">MCPAdapter</span>

<span class="pl-k">async</span> <span class="pl-k">with</span> <span class="pl-en">MCPAdapter</span>(<span class="pl-s">"https://example.com/mcp"</span>) <span class="pl-k">as</span> <span class="pl-s1">adapter</span>:
 <span class="pl-s1">agent</span> <span class="pl-c1">=</span> <span class="pl-en">create_agent</span>(<span class="pl-s">"anthropic:claude-sonnet-5"</span>, <span class="pl-k">await</span> <span class="pl-s1">adapter</span>.<span class="pl-c1">get_tools</span>())
 <span class="pl-s1">result</span> <span class="pl-c1">=</span> <span class="pl-k">await</span> <span class="pl-s1">agent</span>.<span class="pl-c1">ainvoke</span>({<span class="pl-s">"messages"</span>: [{<span class="pl-s">"role"</span>: <span class="pl-s">"user"</span>, <span class="pl-s">"content"</span>: <span class="pl-s">"..."</span>}]})</pre></div>
<p>Valid targets: a URL, a local script path (launched over stdio), an in-process <code>FastMCP</code> server, a config naming several servers at once, or a <code>fastmcp.Client</code> you built yourself.</p>
<p>Tools returned by <code>get_tools()</code> hold the adapter's client, so they stay callable after the context exits — the <code>async with</code> block scopes discovery, not tool lifetime.</p>
<h2>Auth, caching, timeouts — build the client</h2>
<p><code>MCPAdapter</code> takes two arguments: the target and <code>elicitation</code>. Everything else FastMCP supports is configured on a <code>fastmcp.Client</code> that you build and hand over as the target. This is the pattern to reach for whenever you need more than a bare connection:</p>
<div class="highlight highlight-source-python notranslate position-relative overflow-auto"><pre><span class="pl-k">from</span> <span class="pl-s1">fastmcp</span>.<span class="pl-s1">client</span> <span class="pl-k">import</span> <span class="pl-v">Client</span>
<span class="pl-k">from</span> <span class="pl-s1">langchain</span>.<span class="pl-s1">mcp</span> <span class="pl-k">import</span> <span class="pl-v">MCPAdapter</span>

<span class="pl-s1">client</span> <span class="pl-c1">=</span> <span class="pl-en">Client</span>(
 <span class="pl-s">"https://example.com/mcp"</span>,
 <span class="pl-s1">auth</span><span class="pl-c1">=</span><span class="pl-s">"oauth"</span>, <span class="pl-c"># or a bearer token string, or any httpx auth</span>
 <span class="pl-s1">cache</span><span class="pl-c1">=</span><span class="pl-c1">True</span>, <span class="pl-c"># opt-in response caching</span>
 <span class="pl-s1">timeout</span><span class="pl-c1">=</span><span class="pl-c1">30</span>,
)

<span class="pl-k">async</span> <span class="pl-k">with</span> <span class="pl-en">MCPAdapter</span>(<span class="pl-s1">client</span>) <span class="pl-k">as</span> <span class="pl-s1">adapter</span>:
 <span class="pl-s1">tools</span> <span class="pl-c1">=</span> <span class="pl-k">await</span> <span class="pl-s1">adapter</span>.<span class="pl-c1">get_tools</span>()</pre></div>
<p><strong>Auth</strong> accepts <code>"oauth"</code> to run the OAuth flow, a token string for bearer auth, or an <code>httpx.Auth</code> instance for anything custom — see <a href="https://gofastmcp.com/clients/auth" rel="nofollow">FastMCP's auth docs</a>. Per-server headers and auth can also be set in a multi-server config (below).</p>
<p><strong>Caching</strong> is opt-in and off by default: <code>cache=True</code> enables it with defaults, honoring the server's own <code>ttlMs</code> and <code>cacheScope</code> hints; a <code>CacheConfig</code> customizes it. The cache is per-client and in-memory.</p>
<p><strong>Everything else</strong> on <a href="https://gofastmcp.com/clients/client" rel="nofollow"><code>fastmcp.Client</code></a> — <code>timeout</code>, <code>log_handler</code>, <code>progress_handler</code>, <code>message_handler</code>, <code>roots</code>, <code>sampling_handler</code> — works the same way. The adapter passes your client through untouched, so FastMCP behavior is not re-implemented or restricted.</p>
<p>One caveat: with <code>elicitation="interrupt"</code>, the adapter clones your client so it does not overwrite a callback you set. Configuration (auth, cache settings, handlers) carries over to the clone; cached <em>entries</em> do not, since the clone gets its own store.</p>
<p><code>adapter.client</code> exposes the underlying client for prompts, resources, and anything else the adapter does not wrap.</p>
<h2>Multiple servers</h2>
<p>Point the adapter at a config and it fans out to every server through one connection, presenting a single tool list to your agent.</p>
<div class="highlight highlight-source-python notranslate position-relative overflow-auto"><pre><span class="pl-s1">config</span> <span class="pl-c1">=</span> {
 <span class="pl-s">"mcpServers"</span>: {
 <span class="pl-s">"weather"</span>: {<span class="pl-s">"url"</span>: <span class="pl-s">"https://weather.example.com/mcp"</span>},
 <span class="pl-s">"calendar"</span>: {
 <span class="pl-s">"url"</span>: <span class="pl-s">"https://calendar.example.com/mcp"</span>,
 <span class="pl-s">"headers"</span>: {<span class="pl-s">"Authorization"</span>: <span class="pl-s">"Bearer ..."</span>},
 },
 }
}

<span class="pl-k">async</span> <span class="pl-k">with</span> <span class="pl-en">MCPAdapter</span>(<span class="pl-s1">config</span>) <span class="pl-k">as</span> <span class="pl-s1">adapter</span>:
 <span class="pl-s1">agent</span> <span class="pl-c1">=</span> <span class="pl-en">create_agent</span>(<span class="pl-s">"anthropic:claude-sonnet-5"</span>, <span class="pl-k">await</span> <span class="pl-s1">adapter</span>.<span class="pl-c1">get_tools</span>())</pre></div>
<p>With more than one server, tools are namespaced by server name — <code>weather_get_forecast</code>, <code>calendar_create_event</code> — so collisions between servers are impossible. With exactly one server, the adapter connects directly and names are unprefixed. Each entry takes its own <code>headers</code>, <code>auth</code>, <code>transport</code>, and <code>timeout</code>, so servers with different credentials compose in one agent. A local server uses <code>command</code>/<code>args</code> instead of <code>url</code> and is launched over stdio. The config follows FastMCP's <a href="https://gofastmcp.com/integrations/mcp-json-configuration" rel="nofollow">MCP JSON schema</a>, so a config you already use elsewhere works here unchanged.</p>
<h2>Old and new protocol servers, side by side</h2>
<p>MCP has moved from the <code>initialize</code> handshake to <code>server/discover</code>, and servers in the wild sit on both sides of that line. FastMCP negotiates the era per connection, so the adapter reaches either without you selecting one:</p>
<div class="highlight highlight-source-python notranslate position-relative overflow-auto"><pre><span class="pl-c"># handshake-era server over SSE</span>
<span class="pl-s1">legacy</span> <span class="pl-c1">=</span> <span class="pl-en">MCPAdapter</span>(<span class="pl-s">"https://legacy.example.com/sse"</span>)

<span class="pl-c"># modern-era server over streamable HTTP</span>
<span class="pl-s1">modern</span> <span class="pl-c1">=</span> <span class="pl-en">MCPAdapter</span>(<span class="pl-s">"https://modern.example.com/mcp"</span>)</pre></div>
<p>Separate adapters negotiate independently and can run concurrently, each on its own era. This is covered by integration tests that stand up one server of each era and call both.</p>
<p>The one rule worth knowing: <strong>a multi-server config exposes a single era, so its oldest backend sets the era for the whole fleet.</strong> Mixing a handshake-era server into a config pulls the modern backends back to the handshake era — they still work, but era-gated features go with it. Keep a legacy server in its own adapter when you want the others on the modern protocol:</p>
<div class="highlight highlight-source-python notranslate position-relative overflow-auto"><pre><span class="pl-k">async</span> <span class="pl-k">with</span> (
 <span class="pl-en">MCPAdapter</span>({<span class="pl-s">"mcpServers"</span>: {...<span class="pl-s1">modern</span> <span class="pl-s1">servers</span>...}}) <span class="pl-k">as</span> <span class="pl-s1">modern</span>,
 <span class="pl-en">MCPAdapter</span>(<span class="pl-s">"https://legacy.example.com/sse"</span>) <span class="pl-k">as</span> <span class="pl-s1">legacy</span>,
):
 <span class="pl-s1">tools</span> <span class="pl-c1">=</span> <span class="pl-k">await</span> <span class="pl-s1">modern</span>.<span class="pl-c1">get_tools</span>() <span class="pl-c1">+</span> <span class="pl-k">await</span> <span class="pl-s1">legacy</span>.<span class="pl-c1">get_tools</span>()</pre></div>
<h2>Results</h2>
<p>Each tool is async. An MCP tool that runs and reports failure comes back as a <code>ToolMessage</code> with <code>status="error"</code> carrying the server's own error text, so the agent can correct itself and retry. Transport failures and unconvertible content raise instead — a model cannot act on those.</p>
<p>Structured output rides along on the tool message artifact:</p>
<div class="highlight highlight-source-python notranslate position-relative overflow-auto"><pre><span class="pl-k">from</span> <span class="pl-s1">langchain</span>.<span class="pl-s1">mcp</span> <span class="pl-k">import</span> <span class="pl-v">MCPToolArtifact</span>

<span class="pl-s1">artifact</span>: <span class="pl-v">MCPToolArtifact</span> <span class="pl-c1">|</span> <span class="pl-c1">None</span> <span class="pl-c1">=</span> <span class="pl-s1">tool_message</span>.<span class="pl-c1">artifact</span> <span class="pl-c"># None when there is no structured content</span>
<span class="pl-s1">artifact</span>[<span class="pl-s">"structured_content"</span>]</pre></div>
<h2>Elicitation — servers that ask questions mid-call</h2>
<p>Some MCP tools need input before they can finish. Opt in, and the request surfaces as a LangGraph <code>interrupt()</code>, so the human already reviewing the agent's work answers the server too.</p>
<div class="highlight highlight-source-python notranslate position-relative overflow-auto"><pre><span class="pl-s1">adapter</span> <span class="pl-c1">=</span> <span class="pl-en">MCPAdapter</span>(<span class="pl-s1">target</span>, <span class="pl-s1">elicitation</span><span class="pl-c1">=</span><span class="pl-s">"interrupt"</span>)</pre></div>
<p>The capability is opt-in rather than default because declaring it is a promise made on the wire: an agent with no path to a human cannot keep it. Left unset, nothing is declared, and a server whose tool <em>requires</em> an answer declines the call rather than running without one.</p>
<p>The run stops with a typed payload, and resumes with one answer per request key:</p>
<div class="highlight highlight-source-python notranslate position-relative overflow-auto"><pre><span class="pl-k">from</span> <span class="pl-s1">langgraph</span>.<span class="pl-s1">types</span> <span class="pl-k">import</span> <span class="pl-v">Command</span>

<span class="pl-s1">result</span> <span class="pl-c1">=</span> <span class="pl-k">await</span> <span class="pl-s1">agent</span>.<span class="pl-c1">ainvoke</span>({<span class="pl-s">"messages"</span>: [...]}, <span class="pl-s1">config</span>)

[<span class="pl-s1">pause</span>] <span class="pl-c1">=</span> <span class="pl-s1">result</span>[<span class="pl-s">"__interrupt__"</span>]
<span class="pl-s1">pause</span>.<span class="pl-c1">value</span>[<span class="pl-s">"type"</span>] <span class="pl-c"># "mcp_elicitation"</span>
<span class="pl-s1">pause</span>.<span class="pl-c1">value</span>[<span class="pl-s">"tool_name"</span>] <span class="pl-c"># the tool that is waiting</span>
<span class="pl-s1">pause</span>.<span class="pl-c1">value</span>[<span class="pl-s">"requests"</span>] <span class="pl-c"># each question, in the order to ask them</span>

<span class="pl-s1">answer</span> <span class="pl-c1">=</span> {<span class="pl-s">"responses"</span>: {<span class="pl-s1">key</span>: {<span class="pl-s">"action"</span>: <span class="pl-s">"accept"</span>, <span class="pl-s">"content"</span>: {<span class="pl-s">"guests"</span>: <span class="pl-c1">4</span>}}}}
<span class="pl-s1">result</span> <span class="pl-c1">=</span> <span class="pl-k">await</span> <span class="pl-s1">agent</span>.<span class="pl-c1">ainvoke</span>(<span class="pl-en">Command</span>(<span class="pl-s1">resume</span><span class="pl-c1">=</span><span class="pl-s1">answer</span>), <span class="pl-s1">config</span>)</pre></div>
<p>Requests narrow on <code>mode</code>: a <code>"form"</code> request carries <code>requested_schema</code> for the answer to satisfy, a <code>"url"</code> request carries an address for the human to visit. Answers narrow on <code>action</code> — <code>"accept"</code> (with <code>content</code>), <code>"decline"</code> (skip the question, let the call proceed), or <code>"cancel"</code> (abandon the tool call). Requires a checkpointer, as any interrupt does.</p>
<p>Sampling and roots are not answered through interrupts; leave those to your client's own handlers.</p>
<p>Types for handlers — <code>MCPElicitationInterrupt</code>, <code>MCPElicitationRequest</code>, <code>MCPElicitationResponse</code>, <code>MCPElicitationResume</code>, and the <code>ELICITATION_INTERRUPT_TYPE</code> discriminator — live in <code>langchain.mcp.elicitation</code>.</p>
